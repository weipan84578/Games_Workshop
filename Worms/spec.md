# 🐛💥《蟲蟲轟轟隊》Web 遊戲規格書

> **英文名稱：** Wormy Boom Squad
> **日文名稱：** ワーム・ボム隊
> **版本：** 1.0
> **文件狀態：** 可直接進入實作
> **技術：** HTML5 + CSS3 + Vanilla JavaScript + Canvas 2D
> **執行方式：** 不需安裝、不需建置、不需伺服器，直接開啟 `index.html`

---

## 1. 產品摘要

《蟲蟲轟轟隊》是一款原創、可愛風格的單人回合制砲術遊戲。玩家與電腦各控制 3 隻蟲蟲，在隨機產生且能被爆炸挖除的 2D 地形上輪流行動。玩家必須判斷風向、角度、施力、爆炸範圍與地形，使用 10 種功能不同的武器擊敗敵隊。

玩法可讓人聯想到經典回合制砲術遊戲，但遊戲名稱、角色造型、文案、圖示、音效與其他視覺資產都必須原創，不得複製 Team17 或《Worms／百戰天蟲》的商標、美術或音訊。

### 1.1 成功標準

- 在支援的桌面瀏覽器直接雙擊 `index.html` 後，可完成教學與完整對戰。
- 對戰同時包含風力彈道、蓄力、爆風擊退、墜落傷害、可破壞地形與水域淘汰。
- 提供 10 種可正常被玩家及 AI 使用的武器或工具。
- 玩家對 AI 的一局平均落在 10–15 分鐘。
- 桌機支援鍵盤與滑鼠；手機支援橫向觸控操作。
- 所有核心規則能以 Node.js 內建測試器進行單元測試，無第三方套件。
- BGM 尚未提供或載入失敗時，遊戲仍能無錯誤地完整遊玩。

### 1.2 第一版不包含

- 同機多人、網路連線、帳號、排行榜或雲端儲存。
- 戰役、劇情關卡、挑戰關卡或角色養成。
- 未完成對戰的中途存檔。
- 需要伺服器、CDN、套件管理器或編譯器才能執行的功能。
- 忍者繩索、載具、建築物、補給箱或可拾取道具。

## 2. 平台與技術限制

### 2.1 執行環境

- 使用語意化 HTML5、CSS3 與 ES6 等級的 Vanilla JavaScript。
- 遊戲世界、角色、地形、武器與粒子效果使用 Canvas 2D 繪製；選單及 HUD 使用 HTML/CSS。
- 不使用 React、Vue、Three.js、WebGL、npm 執行期套件或任何 CDN。
- 不使用 `fetch()` 載入必要資料，不依賴 Service Worker。
- 瀏覽器端不得依賴 ES Module 的 `import/export`，避免 `file://` 下的 CORS 限制。
- JavaScript 以依賴順序透過傳統 `<script defer>` 標籤載入；各模組以 IIFE／UMD 掛載至 `window.WormsGame`。
- 純邏輯模組同時以 `module.exports` 暴露，供 Node 單元測試 `require()`。
- 所有路徑使用相對路徑，檔名大小寫必須一致。

### 2.2 支援範圍

- 桌面最新版與前一主要版本：Chrome、Edge、Firefox、Safari。
- 行動裝置：iOS Safari、Android Chrome 的近兩個主要版本。
- 最低畫面寬度 320 CSS px；遊戲對戰在手機上只支援橫向。
- 直向手機顯示全螢幕旋轉提示，但主選單與設定仍可操作。
- 桌機目標 60 FPS；主流手機最低可接受 30 FPS。

## 3. 遊戲流程與畫面

### 3.1 應用程式狀態

狀態機固定為：

```text
BOOT → MAIN_MENU
MAIN_MENU → MATCH_SETUP → BATTLE → RESULT
MAIN_MENU → TUTORIAL → MAIN_MENU
MAIN_MENU → STATS → MAIN_MENU
MAIN_MENU → SETTINGS → MAIN_MENU
BATTLE ↔ PAUSED
RESULT → MATCH_SETUP | BATTLE（重賽）| MAIN_MENU
```

- `BOOT`：建立 Canvas、讀取設定、載入可用 BGM、初始化 Web Audio；任何音訊錯誤都不可阻擋進入主選單。
- `BATTLE`：內部另有回合狀態機，詳見第 5 節。
- 切換畫面時應解除不再需要的事件監聽，避免重複輸入與記憶體洩漏。

### 3.2 主選單

顯示原創遊戲 Logo、兩隊可愛蟲蟲的待機動畫，以及下列按鈕：

1. 開始對戰
2. 新手教學
3. 生涯統計
4. 設定

不得在頁面載入時自動播放有聲音的內容。第一次點擊或按鍵後才可解鎖音訊。

### 3.3 對戰設定

| 選項 | 允許值 | 預設值 |
|---|---|---|
| AI 難度 | 簡單、普通、困難 | 普通 |
| 地圖主題 | 隨機、糖果島、森林野餐、冰淇淋雪原 | 隨機 |
| 回合時間 | 20、30、45 秒 | 30 秒 |
| 玩家隊名 | 1–12 個可顯示字元 | 蹦蹦隊 |
| 玩家隊色 | 粉紅、薄荷綠、天空藍、葡萄紫 | 粉紅 |

- 敵隊預設名為「搗蛋隊」，自動選取與玩家不同的高辨識度隊色。
- 隊名須移除首尾空白；空值恢復預設；超過上限時在 UI 阻止繼續輸入。
- 使用者按下開始後才建立地圖種子與對戰狀態。

### 3.4 新手教學

教學使用固定種子與固定角色位置，依序完成四個短階段：

1. 左右移動、跳躍與後空翻。
2. 調整火箭筒角度、觀察風向、蓄力命中目標。
3. 使用手榴彈的拋物線與 3 秒引信越過障礙。
4. 炸開地形，讓練習假人落水。

- 每階段顯示鍵盤與目前輸入裝置對應的操作圖示。
- 可略過單一提示或退出教學。
- 完成狀態寫入設定資料，只控制主選單是否顯示「推薦先玩教學」，不解鎖或封鎖功能。

### 3.5 對戰 HUD

- 頂部左、右分別顯示兩隊名稱、隊色、3 名角色頭像及個別 HP。
- 頂部中央顯示剩餘回合秒數、目前隊伍、目前角色與風向表。
- 風向表顯示箭頭及 `0–10` 級強度；箭頭方向必須與物理加速度一致。
- 底部顯示目前武器、剩餘彈藥、角度、蓄力百分比與操作提示。
- 武器面板顯示 10 種武器；用盡的武器保留顯示但停用。
- 有限彈藥必須同時以數字與圖示狀態呈現。
- 右下提供暫停、鏡頭回到目前角色及觸控裝置專用控制區。

### 3.6 結算、生涯統計與設定

結算畫面顯示勝負、存活角色、對戰時間、總傷害、命中率、最常使用武器與本局地圖種子，並提供：

- 相同設定、相同地圖重賽。
- 相同設定、新地圖重賽。
- 返回對戰設定。
- 返回主選單。

設定畫面包含繁中／英文／日文、BGM 音量、SFX 音量、全部靜音、降低動態效果、鍵盤操作說明、清除生涯統計。清除統計必須二次確認，但不可清除使用者設定。

## 4. 對戰基本規則

### 4.1 隊伍與勝負

- 玩家與 AI 各有 3 隻蟲蟲，每隻初始 100 HP。
- 隊伍交替行動；各隊內依固定循環選出下一隻仍存活的角色。
- HP 降為 0、角色中心落入水面以下，或掉出世界邊界即淘汰。
- 一隊所有角色淘汰時，另一隊立即獲勝。
- 若同一次傷害結算讓雙方全滅，判定平手。
- 勝負只在目前武器、連鎖爆炸、墜落與地形沉降全部結算後判斷。

### 4.2 回合時間與行動

- 預設操作時間 30 秒，可於賽前改為 20 或 45 秒。
- 回合開始先播放最長 0.8 秒的角色提示；這段時間不扣操作秒數。
- 玩家可在開火前任意走路、跳躍、後空翻、選武器及調整鏡頭。
- 大多數武器使用一次後立即進入結算階段；霰彈槍可射擊兩次，第二發須在 8 秒內完成。
- 瞬間移動成功後立即結束操作階段。
- 操作時間歸零但尚未出手時視為跳過回合，不扣除彈藥。
- 投射物或角色動態最長允許結算 8 秒；超時時清除失效投射物並安全進入下一回合，避免卡死。

### 4.3 突發死亡

- 對戰實際遊玩時間累積達 10 分鐘時，在下一回合開始前啟動一次。
- 所有存活角色的目前 HP 直接設為 1；已淘汰角色不復活。
- 顯示明確警告、視覺特效與提示音。
- 從該回合起，每完成一個角色回合，水面向上移動 18 世界像素。
- 水位移動後先檢查溺水與勝負，再開始下一回合。

## 5. 回合狀態機

```text
TURN_INTRO
  → PLAYER_CONTROL | AI_THINKING
  → ACTION_ACTIVE
  → WORLD_SETTLING
  → DAMAGE_SUMMARY
  → CHECK_VICTORY
  → NEXT_TURN | RESULT
```

- `TURN_INTRO`：更新風力、目前角色、HUD 與鏡頭。
- `PLAYER_CONTROL`：接受移動、瞄準、武器與施力輸入。
- `AI_THINKING`：AI 產生合法行動計畫；玩家輸入被忽略，但暫停仍有效。
- `ACTION_ACTIVE`：模擬投射物、引信、武器特殊行為與連鎖反應。
- `WORLD_SETTLING`：等待角色落地、爆炸完成、地形更新；連續 0.6 秒沒有顯著移動即可結束。
- `DAMAGE_SUMMARY`：集中顯示傷害數字與淘汰結果。
- `CHECK_VICTORY`：處理全滅、平手及突發死亡。
- 暫停只凍結模擬與遊戲計時，不得重建當前狀態。

## 6. 角色移動與物理

### 6.1 座標與時間

- 邏輯世界尺寸固定為 `1920 × 1080` 世界像素，座標原點位於左上，`+x` 向右、`+y` 向下。
- 物理使用 `1/120 秒` 固定時間步進；每幀累積時間最多 `0.25 秒`，避免切回分頁後爆衝。
- 畫面以 `requestAnimationFrame` 呈現，必要時在前後兩個物理狀態間插值。
- 全域重力為 `900 px/s²`。
- 角色碰撞以半徑 18 px 的圓形／膠囊近似，繪圖尺寸約 `44 × 52 px`。

### 6.2 風力

- 每個角色回合開始，以對戰 PRNG 產生 `-100` 至 `+100 px/s²` 的水平加速度。
- HUD 將絕對值映射為 0–10 級；`0–4` 顯示 0 級，之後每 10 為一級。
- 正值吹向右，負值吹向左。
- 各武器透過 `windFactor` 決定承受比例；加速度公式為 `ax = wind × windFactor`。

### 6.3 基本動作

| 動作 | 規則 |
|---|---|
| 走路 | 水平速度 110 px/s；可攀爬不超過 35° 的連續坡面 |
| 跳躍 | 起始垂直速度 -360 px/s，水平速度保留目前移動方向 |
| 後空翻 | 朝面向反方向 150 px/s、垂直速度 -470 px/s |
| 空中控制 | 只允許水平速度朝輸入方向微調，最大改變量為地面加速度的 25% |

- 站立檢測必須從角色腳底取樣地形，不可只使用矩形碰撞。
- 角色被爆風擊飛後，在落地並穩定前不可再次操作。
- 陡坡或被挖空的腳下應自然滑落，不得懸浮。

### 6.4 墜落與爆炸傷害

- 落地前向下速度不超過 `420 px/s` 時不受墜落傷害。
- 超過門檻時，傷害為 `floor((impactSpeed - 420) / 12)`，上限 60。
- 爆炸傷害採距離衰減：`ceil(maxDamage × (1 - distance / radius))`；爆炸半徑外為 0。
- 角色碰撞圓與爆炸中心重疊時，距離以角色中心計算並限制最小為 0。
- 爆風衝量沿爆炸中心至角色中心方向套用，強度同樣按距離線性衰減。
- 爆炸可傷害操作者與同隊角色，所有隊伍使用完全相同的規則。
- 同一爆炸對同一角色只能計算一次傷害。

## 7. 隨機地形與水域

### 7.1 可重現亂數

- 每局持有一個 32 位元無號整數 `seed`。
- 地形、出生點、回合風力與 AI 的隨機誤差都由各自從主 seed 派生的 PRNG stream 取得，避免 AI 呼叫次數改變地形或風力。
- PRNG 固定使用 `mulberry32`；文字 seed 先使用固定的 32 位元字串雜湊轉換。
- 相同版本、相同 seed 與相同設定必須產生相同初始地形及出生點。

### 7.2 生成規則

- 地形採連續高度曲線加 2–4 個山丘、凹谷或拱洞，底部連接世界下緣。
- 可玩地表高度限制在 `y = 360–820`；初始水面為 `y = 1010`。
- 地圖左右各保留至少 70 px 安全邊界。
- 生成後尋找 6 個出生平台；平台寬至少 100 px、局部坡度不超過 18°、角色頭上保留 70 px 空間。
- 玩家與 AI 出生位置交錯分布，任意兩個出生點水平距離至少 180 px，同隊不可全部集中在地圖同一側。
- 最多重試 20 次；仍找不到合法配置時使用內建保底種子與地形模板。

### 7.3 可破壞遮罩

- 使用與世界同尺寸的地形 Canvas 作為實際 alpha mask；alpha 大於等於 128 視為實心。
- 視覺地形與碰撞遮罩必須來自同一資料來源，避免看得到卻穿透或看不到卻碰撞。
- 爆炸以 `destination-out` 挖除圓形或武器指定形狀，再只更新受影響的髒矩形碰撞資料。
- 地形破壞後立即重新檢查受影響角色是否仍有支撐，並進入沉降模擬。
- 世界外左右及下方視為死亡區；上方允許投射物暫時飛出並在合理時間內返回。

### 7.4 三種主題

| 主題 | 主色與地形 | 背景裝飾 |
|---|---|---|
| 糖果島 | 草莓粉、奶油黃、薄荷綠 | 棒棒糖樹、軟糖石、棉花糖雲 |
| 森林野餐 | 嫩綠、焦糖棕、莓果紅 | 蘑菇、野餐旗、圓葉樹 |
| 冰淇淋雪原 | 淡藍、薰衣草紫、香草白 | 冰淇淋山、糖針、果凍冰塊 |

裝飾物不得參與碰撞，也不得遮住角色、彈道提示或 HUD。三個主題只改變視覺，不改變物理與難度。

## 8. 武器系統

### 8.1 共用規則

- 所有武器定義集中在不可變的 `WeaponRegistry`，HUD、玩家、AI 與測試共用同一份資料。
- 角度以角色面向為基準，允許瞄準 `-80°` 至 `+80°`；畫面顯示換算後的直觀仰角。
- 蓄力武器按住後於 1.2 秒達到 100%；最小有效力道 10%。
- 瞄準時只顯示依目前角度、最低示範力道與當前風力推算的前 0.65 秒短段虛線，不顯示完整落點。
- 直接選點武器必須在確認合法目標後才扣彈藥。
- 有限彈藥按「隊伍」計算，不是每隻角色各自擁有。

| 空襲 | 1 | 選擇地表目標 | 每枚 24 | 每枚 42 px | 0 | 5 枚飛彈由上方斜向落下，水平間距 48 px |
| 綿羊炸彈 | 1 | 放置後自動前進 | 65 | 78 px | 0 | 140 px/s，自動小跳；再次觸發或 8 秒後爆炸 |
| 神聖手榴彈 | 1 | 蓄力，180–560 px/s | 90 | 100 px | 0.05 | 3 秒引信，最後 1 秒停留時播放提示音 |
| 瞬間移動 | 2 | 點選合法地點 | 0 | 0 | 0 | 移動目前角色並結束回合 |

### 8.3 武器特殊驗證

- 空襲目標可位於任意可見世界座標，但飛彈起點不得生成於 HUD 區域；世界空間與畫面空間必須正確換算。
- 空襲方向依風向反向切入；零風時由隨機但可重現的左或右方向切入。
- 地雷可被爆炸、子彈或墜落物提早引爆；連鎖爆炸不得重複結算同一枚地雷。
- 綿羊遇到不高於 32 px 的障礙時自動跳躍，抵達懸崖會繼續前進並受重力影響；落水時立即爆炸。
- 瞬移位置須位於實心地表上、角色膠囊不重疊地形或其他角色、頭部淨空至少 52 px，且角色中心高於水面 30 px；非法位置顯示紅色預覽，不消耗彈藥。
- 霰彈槍第一發後可移動及重新瞄準，但不可更換武器；第二發完成或 8 秒到期後進入結算。

## 9. AI 設計

### 9.1 共通流程

AI 每回合依序：

1. 掃描可攻擊敵人、友軍、自身、水域、附近地形及可用彈藥。
2. 產生移動前與數個可安全抵達位置的候選狀態。
3. 對每種可用武器抽樣合法角度、力度或目標點，使用與玩家相同的物理預測器模擬。
4. 依預期敵方傷害、友軍傷害、自傷、地形優勢、落水機率、彈藥價值及命中率評分。
5. 選出最高分的合法方案，再加入該難度的可重現誤差。
6. 透過正常輸入／動作介面執行，不得直接修改 HP、位置或彈道。

AI 可評估的模擬數量設硬上限，單回合思考牆鐘時間不得超過 1.5 秒。超時時使用目前最佳方案；若沒有合法攻擊，優先移動至安全地點，其次瞬移，最後跳過回合。

### 9.2 難度差異

| 難度 | 候選模擬上限 | 角度誤差 | 力度誤差 | 戰術能力 |
|---|---:|---:|---:|---|
| 簡單 | 60 | ±8° | ±14% | 偏好最近目標，較少移動，不精算連鎖與水域 |
| 普通 | 180 | ±4° | ±7% | 評估自傷、友軍、地形與有限彈藥價值 |
| 困難 | 420 | ±1.5° | ±3% | 評估爆風落水、連鎖爆炸、移動後射線與保留稀有武器 |

- 所有誤差使用 AI 專用 seeded PRNG，不可使用 `Math.random()`。
- AI 不保證命中；困難難度仍必須保留小幅誤差。
- AI 必須遵守射程、彈藥、回合時間、合法瞬移點及友軍傷害規則。

## 10. 操作方式與鏡頭

### 10.1 鍵盤

| 功能 | 按鍵 |
|---|---|
| 左右移動 | `A/D` 或 `←/→` |
| 跳躍 | `W` |
| 後空翻 | `S` |
| 調整瞄準角度 | `↑/↓` |
| 蓄力／開火 | 按住／放開 `Space` |
| 上一／下一武器 | `Q/E` |
| 開啟武器面板 | `R` |
| 回到目前角色 | `F` |
| 暫停 | `Escape` |

- 所有遊戲按鍵在焦點位於表單欄位時停用。
- 不得攔截瀏覽器必要的系統快捷鍵。

### 10.2 滑鼠與觸控

- 點擊武器面板選擇武器。
- 從目前角色旁的瞄準控制點向外拖曳：方向決定角度、距離決定力道；放開後開火。
- 拖曳開始點不在瞄準控制點時，不得意外開火。
- 直接選點武器以半透明預覽顯示有效／無效位置，再按一次確認。
- 手機橫向顯示左側移動、跳躍、後空翻按鈕，以及右側瞄準、蓄力、武器與鏡頭按鈕。
- 所有觸控目標至少 `44 × 44 CSS px`，並考慮 `safe-area-inset-*`。

### 10.3 鏡頭

- 鏡頭限制在世界邊界內，縮放範圍 `0.65–1.5`。
- 回合開始聚焦目前角色；投射物發射後平滑跟隨投射物；爆炸時短暫保留爆炸區域。
- 桌機可用滑鼠中鍵／右鍵拖動畫面與滾輪縮放；觸控使用雙指平移與縮放。
- 手動移動鏡頭後暫停自動跟隨，按下回焦按鈕恢復。
- 「降低動態效果」開啟時取消鏡頭晃動、快速縮放及大幅視差，只保留必要跟隨。

## 12. 音訊

### 12.1 BGM 檔案契約

使用者日後提供以下三個檔案；實作必須先完成路徑與播放時機：

| 路徑 | 播放時機 | 規則 |
|---|---|---|
| `assets/audio/bgm/menu.mp3` | 主選單、設定、統計、對戰設定 | 循環播放 |
| `assets/audio/bgm/battle.mp3` | 教學與一般對戰 | 循環播放 |
| `assets/audio/bgm/result.mp3` | 結算畫面 | 循環播放 |

- 切換曲目使用 400 ms 淡出及 400 ms 淡入。
- BGM 元素以 `preload="metadata"` 建立，不得讓缺檔阻擋 `BOOT`。
- `play()` Promise 被瀏覽器拒絕或檔案不存在時只記錄一次警告並保持靜音，不顯示阻斷式錯誤。
- 音樂在頁面隱藏時暫停；返回後依原本狀態恢復。

### 12.2 程式合成音效

使用 Web Audio API 的 oscillator、noise buffer、filter 與 gain envelope 合成，不要求外部 SFX 檔。至少提供：

- UI 點擊、返回、錯誤、確認。
- 跳躍、後空翻、落地、受傷、落水。
- 火箭發射、霰彈槍、揮棒、引信、地雷啟用。
- 小型爆炸、大型爆炸、連鎖爆炸。
- 綿羊提示、神聖手榴彈最後一秒提示。
- 回合開始、倒數警告、突發死亡、勝利、失敗。

第一次使用者互動後才能建立或 resume `AudioContext`。BGM 與 SFX 各有 `0–100` 音量，預設 BGM 45、SFX 70；靜音不改寫原本滑桿值。

## 13. 多語系與無障礙

### 13.1 語言

- 支援 `zh-Hant`、`en`、`ja`，預設依瀏覽器語言選擇，不支援時回退 `zh-Hant`。
- 所有畫面文字、武器名稱、說明、AI 難度、錯誤、ARIA label 與教學文案必須使用翻譯 key。
- 缺少翻譯時回退繁中並在開發主控台提出一次警告，不得顯示 `undefined` 或 key 名稱。
- 切換語言後立即更新目前畫面，不需重新整理或重開對戰。

### 13.2 無障礙

- HTML 控制元件可用 Tab、Shift+Tab、Enter、Space 操作，焦點樣式清楚可見。
- 文字及關鍵控制項達 WCAG AA 對比；主文字與背景至少 4.5:1。
- 回合、武器耗盡、非法目標與勝負透過 `aria-live` 區域提供簡短提示。
- Canvas 提供文字替代摘要，說明目前角色、HP、武器、風向與回合時間。
- 音訊提示皆有同步視覺提示；隊伍辨識不得只靠顏色。
- 尊重 `prefers-reduced-motion`，並允許玩家在設定中覆寫。

## 15. 公開模組契約

所有公開函式必須附 JSDoc。模組透過 `window.WormsGame` 提供相同名稱，Node 環境則匯出可測試的純函式／類別。

### 15.1 核心型別

```js
// 世界中的向量
{ x: number, y: number }

// 對戰設定
MatchConfig {
  seed: number,
  aiDifficulty: "easy" | "normal" | "hard",
  theme: "candy" | "forest" | "icecream",
  turnSeconds: 20 | 30 | 45,
  playerTeamName: string,
  playerColor: "pink" | "mint" | "sky" | "grape"
}

// 武器共同定義
WeaponDefinition {
  id: string,
  ammo: number | Infinity,
  category: "projectile" | "hitscan" | "melee" | "placed" | "targeted",
  maxDamage: number,
  blastRadius: number,
  terrainRadius: number,
  windFactor: number,
  execute(context, command): WeaponResult
}
```

### 15.2 必要模組

| 模組 | 必要公開能力 |
|---|---|
| `GameState` | 建立／重設對戰、切換應用與回合狀態、建立只讀快照 |
| `GameLoop` | 固定步進、暫停、恢復、最大累積時間限制 |
| `PhysicsEngine` | 投射物積分、角色移動、地形取樣、爆炸與墜落傷害 |
| `TerrainMask` | seeded 生成、`isSolid(x,y)`、`carveCircle()`、出生點驗證 |
| `WeaponRegistry` | `get(id)`、`list()`、彈藥初始化與共同定義驗證 |
| `TurnManager` | 開始回合、倒數、行動結算、輪替、突發死亡、勝負判斷 |
| `AIController` | `planTurn(snapshot, difficulty, rng)`；不得直接改變遊戲狀態 |
| `InputManager` | 將鍵盤、滑鼠與觸控轉換成一致的語意 command |
| `CameraController` | 世界／螢幕座標換算、跟隨、平移、縮放、邊界限制 |
| `Renderer` | 只讀取 state snapshot，不持有規則真相或直接改變物理 |
| `AudioManager` | 解鎖、曲目切換、程式 SFX、音量、靜音及安全降級 |
| `I18n` | 語言切換、插值、回退與翻譯完整性檢查 |
| `StorageService` | 讀取、驗證、合併預設、儲存設定、更新／清除統計 |

輸入層統一產生 `moveLeft`、`moveRight`、`jump`、`backflip`、`aim`、`chargeStart`、`fire`、`selectWeapon`、`selectTarget`、`confirmTarget`、`cameraPan`、`cameraZoom`、`pause` 等 command；核心規則不得直接檢查實體按鍵。

## 16. 效能與穩定性

- 只重繪必要 Canvas layer；背景、地形、動態實體與特效分層。
- 地形 alpha 讀取以髒矩形快取，不得每一物理步驟呼叫整張 `getImageData()`。
- 粒子設總量上限：桌機 500、手機 250；超出時丟棄最舊的非關鍵粒子。
- AI 模擬使用簡化碰撞快照，不得阻塞 UI 超過 100 ms；較大批次以時間切片處理。
- 所有 timeout、animation frame、音訊節點與事件監聽在離開對戰時釋放。
- 分頁隱藏時暫停物理與回合計時，返回時不得補算隱藏期間的時間。
- 視窗縮放或旋轉只重算呈現與輸入映射，不重建地圖或重設對戰。
- 非有限數值、遺失投射物、非法 AI command 或音訊例外必須被隔離；不得使遊戲迴圈永久停止。

## 17. 單元測試與驗收

### 17.1 測試執行方式

`package.json` 僅用於測試便利性，不是遊戲執行依賴：

```json
{
  "name": "wormy-boom-squad",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "test": "node --test tests/*.test.js"
  }
}
```

允許使用 Node 內建的 `node:test` 與 `node:assert/strict`，不得安裝 Jest、Vitest、jsdom 或其他第三方測試套件。

### 17.2 必測案例

#### 物理

- 無風火箭的水平／垂直位置符合固定時間步進結果。
- 正、負風力分別使可受風投射物向正確方向偏移。
- 不同畫面幀率輸入下，固定時間步進產生近似相同結果。
- 爆炸中心、半徑邊緣與半徑外的傷害分別為最大、接近零、零。
- 自傷與友軍傷害會正常套用；同一爆炸不重複傷害。
- 墜落速度在門檻上下及極端值時得到正確傷害和上限。

#### 地形

- 相同 seed 產生相同高度取樣、出生點與主題資料。
- 不同 seed 通常產生不同地形。
- 6 個出生點皆有足夠平台、淨空、間距且高於水面。
- `carveCircle()` 只移除圓內實心像素，圓外資料不變。
- 挖除腳下地形後角色進入下落狀態。
- 生成失敗達重試上限時採用合法保底模板。

#### 武器

- 10 個 ID 唯一，所有必要欄位及數值範圍合法。
- 無限與有限彈藥消耗正確；非法目標與逾時跳過不扣彈藥。
- 手榴彈、香蕉炸彈與神聖手榴彈依各自引信爆炸。
- 霰彈槍只允許兩發，第二發後結束行動。
- 空襲產生 5 枚且位置、間距、方向正確。
- 地雷延遲啟用、進入範圍、延遲爆炸與連鎖保護正確。
- 瞬移拒絕地形內、水下、世界外與角色重疊位置。

#### 回合與勝負

- 隊伍交替，已淘汰角色被跳過，同隊循環順序穩定。
- 時間到未攻擊時跳過且不耗彈藥。
- 世界尚未穩定時不得提早切換回合。
- 單隊全滅、雙方同時全滅分別得到勝利與平手。
- 10 分鐘前不啟動突發死亡；啟動時存活角色設為 1 HP，之後每回合水面上升 18 px。
- 暫停及分頁隱藏期間不扣回合或突發死亡時間。

#### AI

- AI 回傳的武器仍有彈藥，角度、力度與目標均合法。
- 所有難度使用與玩家相同的預測器與傷害規則。
- 固定 seed 下決策可重現。
- 困難 AI 的平均誤差小於普通，普通小於簡單。
- 明顯會造成己方全滅的方案在存在安全攻擊時不會被選中。
- 無合法射擊時能移動、瞬移或跳過，不會卡死。

#### 儲存、多語與結構

- 儲存資料缺欄、錯型、越界、舊版或損壞 JSON 時安全回復。
- 清除統計保留設定。
- 三種語言擁有完全相同的 key 集合，缺 key 時正確回退繁中。
- 所有必要 HTML、CSS、JS 與 SVG 路徑存在且大小寫吻合。
- 程式不存在必要資源的絕對路徑、CDN、`fetch()` 或瀏覽器端 `type="module"`。
- 三個 BGM 路徑固定正確，但音訊檔可在開發階段不存在。

### 17.3 手動驗收

1. 在每個支援的桌面瀏覽器以檔案方式直接開啟 `index.html`，不啟動 server。
2. 在三種地圖與三種 AI 難度各完成至少一局。
3. 驗證鍵盤蓄力、滑鼠拖曳及手機觸控拖曳都能瞄準與開火。
4. 在手機橫向完成一局；直向時只能看到清楚的旋轉提示，不可誤觸戰鬥。
5. 移除三個 BGM 檔後重開遊戲，確認選單、戰鬥、SFX 與結算仍正常。
6. 戰鬥中暫停、切換分頁、旋轉裝置與縮放視窗，確認計時及狀態沒有跳動或重設。
7. 觸發爆炸連鎖、角色墜落、落水、雙方同時全滅及突發死亡。
8. 用鍵盤完整操作所有非 Canvas UI，檢查焦點順序、ARIA 提示與降低動態效果。
