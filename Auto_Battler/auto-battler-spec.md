## 1. 專案總覽

### 1.1 遊戲定義

| 項目 | 說明 |
|---|---|
| 遊戲類型 | Auto Battler（自走棋） |
| 核心玩法 | 買兵 → 布陣 → 自動開打（純數值 / AI 計算戰鬥結果） |
| 平台 | 純前端網頁，`index.html` 雙擊即玩 |
| 目標族群 | 全年齡、休閒策略玩家，介面走可愛風格 |
| 語言 | 繁體中文 / 英文 / 日文（可即時切換） |

### 1.2 設計核心原則

- **零安裝、零建置**：不依賴 npm / webpack / vite 等建置工具，也不需要啟動任何 local server，直接用瀏覽器打開 `index.html` 即可運行。
- **模組化架構**：CSS 與 JS 皆依功能拆分成獨立檔案，`index.html` 用 `<link>` 與 `<script>` 明確引入，不使用打包工具。
- **手機優先的可玩性**：所有操作元件（按鈕、拖曳、商店）在小螢幕上都不可以遮住戰鬥棋盤視野。
- **輕鬆可愛的視覺基調**：大字體、高對比、多套配色主題、大量可愛圖示，讓遊戲一眼就是「好親近、看得懂」。

## 2. 技術規格與限制

### 2.1 技術棧

| 分類 | 技術 | 備註 |
|---|---|---|
| 標記語言 | HTML5 | 單一入口 `index.html` |
| 樣式 | 原生 CSS3（分檔案） | 使用 CSS 變數（Custom Properties）做主題切換 |
| 邏輯 | 原生 JavaScript（ES6+，分檔案） | 不使用框架（React/Vue 等），避免需要 build |
| 圖形渲染 | HTML/CSS + Canvas（戰鬥特效可選用 Canvas 2D） | 不使用 WebGL，確保低階手機也流暢 |
| 音訊 | Web Audio API（`AudioContext` + `GainNode`） | 用於精準控制音量倍率與淡入淡出 |
| 儲存 | `localStorage` | 存檔、設定、語言、音量皆本地保存 |
| 相依套件 | **無任何第三方套件 / CDN 依賴**（可離線執行） | 字型可選擇內嵌 base64 或系統字型 fallback |

### 2.2 硬性限制

- ❌ 不可使用 `import`/`export` 的 ES Module 語法搭配 `type="module"` 若會導致 `file://` 協定下 CORS 阻擋（多數瀏覽器對 `file://` 開啟的 module script 會有跨源限制）。
  - ✅ 解法：JS 一律採用**傳統 `<script src="...">` 依序載入**的全域命名空間方式（例如 `window.AutoBattler = window.AutoBattler || {}`），避免使用 ES Module，確保純雙擊開檔也能執行。
- ❌ 不可要求使用者安裝 Node.js、執行 `npm install`、`npm run dev` 等指令。
- ❌ 不產生 `README.md`（依需求第 16 點，待完成後另行生成）。
- ✅ 所有資源（圖片、音樂、字型）皆使用**相對路徑**，確保搬移資料夾後仍可執行。

## 4. RWD 響應式設計規範

### 4.1 斷點定義

| 裝置 | 寬度範圍 | 佈局策略 |
|---|---|---|
| 手機直向 | ≤ 480px | 單欄、棋盤縮放置中、操作鍵移至畫面下緣安全區 |
| 手機橫向 / 小平板 | 481px–767px | 棋盤置中、商店可左右滑動 |
| 平板 | 768px–1024px | 棋盤 + 側欄資訊並排 |
| 桌機 | ≥ 1025px | 完整三欄式（左：羈絆資訊／中：棋盤／右：商店＋操作） |

### 4.2 不遮擋原則（重點需求）

- **戰鬥棋盤永遠是視覺主體**，任何 UI 元件不得覆蓋在棋盤上方，除非是使用者主動點開的彈窗。
- 手機版操作按鍵（開始戰鬥、購買、上鎖商店、購買經驗）一律置於**畫面最下方浮動操作列（HUD Bar）**，並且：
  - 使用 `env(safe-area-inset-bottom)` 避開 iPhone 底部手勢列。
  - HUD Bar 採半透明可收合設計，非戰鬥階段才展開完整按鈕，戰鬥階段自動縮小為極簡狀態列。
  - 棋盤區域使用 `calc(100vh - header高度 - HUD高度)` 動態計算可視高度，確保永遠完整顯示、不被裁切或蓋住。
- 商店列在手機版採**水平滑動（horizontal scroll）**，不佔用垂直空間。
- 所有彈窗（說明、設定、結算）皆為**置中 Modal + 遮罩**，關閉後完全不影響棋盤佈局。

### 4.3 觸控優化

- 所有可點擊元件最小尺寸 `44x44px`（符合行動裝置觸控標準）。
- 棋子支援「拖曳」與「點擊選取 + 點擊目標格」兩種放置方式，觸控裝置預設使用後者以避免誤觸。
- 長按棋子顯示詳細資訊卡（Tooltip），放開手指才觸發移動，避免與拖曳手勢衝突。

### 4.4 螢幕方向

- 手機建議直向遊玩，但不強制鎖定方向；橫向時自動切換為左右分欄精簡版佈局。
- 若偵測極窄視窗（< 320px），顯示「請放大視窗或使用直向手機」提示，但仍保持可玩。

## 5. 視覺與美術風格

### 5.1 整體美術方向

- **主風格**：可愛療癒系（Kawaii / Chibi），角色為 Q 版比例（大頭小身），圓潤造型、圓角邊框。
- **輔助風格**：搭配「擬真材質」細節（第 13 點需求）——例如棋盤地板使用木紋/絨布材質貼圖、金幣圖示有光澤漸層與陰影、卡片邊框有仿金屬/仿緞面質感，讓可愛角色站在「有立體感的真實場景」中，兩者結合成「可愛 Q 版角色 + 精緻寫實場景」的混合風格。
- 大量使用圓角（border-radius ≥ 12px）、柔和陰影（box-shadow 模糊大、擴散小）、漸層背景。
- 裝飾元素：雲朵、星星、愛心、彩虹、花朵、氣泡等圖案散佈於背景與 UI 邊框角落（不影響閱讀）。

### 5.2 視覺層次

| 層級 | 內容 | z-index |
|---|---|---|
| 背景層 | 主題背景圖 + 裝飾圖案（低透明度、緩慢飄動動畫） | 0 |
| 場景層 | 棋盤、角色 | 10 |
| UI 層 | HUD、按鈕、商店 | 20 |
| 特效層 | 戰鬥特效、升星光效、傷害數字 | 30 |
| 彈窗層 | 說明、設定、結算 Modal | 40 |
| 提示層 | Toast 通知、教學指引箭頭 | 50 |

## 6. 字體與配色系統

### 6.1 字體規範（重點需求：字體要大、清楚明確）

| 用途 | 字級（桌機 / 手機） | 字重 |
|---|---|---|
| 主標題（Logo、頁面標題） | 40px / 28px | 800（extra bold） |
| 次標題（區塊標題） | 28px / 22px | 700 |
| 內文（說明文字） | 20px / 18px | 500 |
| 按鈕文字 | 22px / 18px | 700 |
| 數值顯示（金幣、血量、傷害） | 26px / 20px，等寬數字 | 800 |
| 提示 / 註解文字 | 16px / 14px（全站最小字級，不再更小） | 400 |

- 字體選用**圓體 / 可愛風無襯線字型**（例如思源圓體、Baloo 2、Fredoka 類型風格），確保中英日三語皆有對應字重與清晰度。
- 全站文字對比度需符合 **WCAG AA 標準**（對比度 ≥ 4.5:1），避免淺色字疊在淺色背景上看不清楚。
- 重要數值（傷害、金幣增減）加上文字陰影或描邊，確保在任何背景色上都清晰可辨。

### 6.2 配色主題系統（重點需求：多樣色彩可選＋可愛風主題）

透過 CSS 變數 + `<html data-theme="...">` 切換，主題清單：

| 主題名稱 | 代碼 | 主色調 | 適用情境 |
|---|---|---|---|
| 🌸 可愛粉萌（預設） | `cute` | 櫻花粉 #FFD6E8、奶油黃 #FFF3B0、天空藍 #C6E7FF | 預設主題，大量愛心/星星圖案 |
| 🌊 海洋清新 | `ocean` | 珊瑚藍 #7FDBFF、湖水綠 #A0E7E5、白沙 #FFFDF7 | 清爽風格 |
| 🌅 夕陽暖橘 | `sunset` | 蜜橘 #FFB26B、蜜桃粉 #FFD3B0、淡紫 #E5B8F4 | 溫暖風格 |
| 🌲 森林綠意 | `forest` | 抹茶綠 #B5EAD7、奶茶棕 #E8D5B7、鵝黃 #FFF1B6 | 自然風格 |
| 🌌 星空夢幻 | `galaxy` | 薰衣草紫 #C3AED6、午夜藍 #6C7CE0、星光金 #FFE8A3 | 夢幻風格 |
| 🌙 護眼深色 | `dark` | 深灰藍 #2B2D42、霧紫 #8D99AE、亮薄荷 #A0FFE0 | 夜間 / 護眼模式 |

- 每個主題除了主色，皆需定義：`--color-primary`、`--color-secondary`、`--color-accent`、`--color-bg`、`--color-surface`、`--color-text`、`--color-text-inverse`、`--color-success`、`--color-danger`、`--color-warning`，確保元件在不同主題下都能正確配色，**不會出現文字與背景同色導致看不見的情況**。
- 每個主題皆搭配對應的裝飾圖案風格（例如 galaxy 主題背景飄星星、cute 主題背景飄愛心與雲朵），強化「可愛風主題」的沉浸感。
- 設定頁提供**即時預覽**色票，點擊即切換並存入 `localStorage`，重新整理後維持使用者選擇。

## 8. 遊戲核心玩法機制

### 8.1 遊戲流程（回合制）

```
[準備階段] → [商店購買 / 布陣] → [自動戰鬥階段] → [結算階段] → 回到 [準備階段]
```

| 階段 | 說明 | 時間限制 |
|---|---|---|
| 準備階段 | 商店刷新，玩家用金幣購買棋子、調整陣容 | 建議 30 秒倒數（可跳過） |
| 布陣階段 | 拖曳/點擊將棋子放上棋盤格 | 併入準備階段時間 |
| 自動戰鬥階段 | 雙方棋子依 AI 邏輯自動出手，純數值計算勝負 | 依戰鬥複雜度，約 15–30 秒 |
| 結算階段 | 顯示勝負、扣血、金幣結算、連勝/連敗計算 | 3–5 秒過場 |

### 8.2 經濟系統

- 每回合基礎收入金幣（例：5 金）。
- 利息機制：每持有 10 金幣獲得 1 金幣利息（上限例如 5 金）。
- 連勝 / 連敗獎勵：連續勝利或落敗達門檻可獲得額外金幣。
- 商店可花費金幣「鎖定」陣容（不刷新）或「刷新」商店（花費金幣重抽）。
- 升等級（Level Up）花費金幣，等級決定場上可放置棋子上限與商店出現高費棋子的機率。

### 8.3 棋子與羈絆系統

- 棋子分為**費用等級 1★–5★**（星級對應購買費用與強度）。
- 同名棋子不論目前星數都能自動吃牌；每吃掉一張同名棋子就增加 1 點卡牌經驗，經驗需求依序為 1→2 星 2 點、2→3 星 3 點、3→4 星 4 點、4→5 星 5 點，滿經驗立即升星，最高 5 星。數值公式為 `基礎值 × 星級係數`，係數為 1★=1.0、2★=1.8、3★=3.2、4★=4.8、5★=6.8；卡牌價格則依星級倍率 1、2、4、7、11 倍成長。
- 購買卡牌經驗會同時增加所有已擁有棋子（棋盤與備戰區）的經驗，並依目前最高星級調整效率：1 星為花費 4 金幣獲得 4 EXP，之後依序為 6/3、8/2、10/1，最高五星為 12/1；玩家等級經驗仍由回合結算提供。
- 每個棋子擁有**種族**與**職業**標籤，場上湊齊特定數量觸發羈絆加成（例如：3 隻「精靈」羈絆 → 全體攻速 +15%）。
- 每個棋子擁有主動或被動技能，戰鬥中依「法力值 / 冷卻時間」自動觸發。

### 8.4 自動戰鬥計算邏輯（純數值計算，需求重點）

- 戰鬥開始前，複製雙方陣容的棋子快照（含當前血量、屬性、羈絆加成後的最終數值）。
- 戰鬥採用**離散時間步（tick-based）模擬**：每個 tick（例如 0.1 秒）計算：
  1. 攻速決定的行動判定（`行動計時器 += 攻速`，達到閾值即出手）。
  2. 選擇攻擊目標（預設：最近敵人 / 可切換為最低血量優先）。
  3. 傷害公式：`實際傷害 = max(1, 攻擊力 × (1 - 防禦力 / (防禦力 + 100)))`（防禦遞減公式，避免防禦無限增長導致零傷害）。
  4. 技能法力值累積（受擊 / 攻擊皆可獲得法力值），滿值觸發技能效果。
  5. 死亡判定與移除。
- 整場戰鬥**全自動運算完成後才播放戰鬥動畫**（或即時模擬同步播放皆可），玩家全程不可操作，僅能觀看與（可選）2 倍速播放。
- 戰鬥結果：清點雙方存活棋子，判定勝負；輸家依「對方存活棋子數量與星級」計算扣血量。

### 8.5 勝敗條件

- 玩家血量歸零則淘汰（若為多人／PvE 混合模式）。
- 單機版可設計為「生存波數挑戰」：玩家血量歸零即結束遊戲，記錄存活回合數與最高評分。

## 11. 音樂與音效系統

> 重點需求：多首鋼琴輕快 BGM、高音輕脆音效、遊戲中 BGM 音量放大為原本的 10 倍。

### 11.1 BGM 規劃

| 曲目用途 | 風格 | 建議數量 |
|---|---|---|
| 主畫面 BGM | 鋼琴輕快、明亮大調 | 1 首（循環播放） |
| 準備/布陣階段 BGM | 鋼琴輕快、俏皮節奏 | 2–3 首（隨機輪播，避免單調） |
| 自動戰鬥階段 BGM | 鋼琴節奏稍快、帶緊張感但仍輕快 | 1–2 首 |
| 勝利／結算 BGM | 短促歡快鋼琴音樂 | 1 首（非循環，播放一次） |

- 所有 BGM 之間切換使用 **1–2 秒淡入淡出（fade in/out）**，避免生硬切換。
- BGM 清單存放於 `assets/audio/bgm/`，由 `audioManager.js` 統一管理播放佇列與隨機輪播邏輯。

### 11.2 音效（SFX）規劃

| 情境 | 音效風格 |
|---|---|
| 按鈕點擊 | 高音清脆「叮」聲 |
| 購買棋子 | 清脆金幣「叮鈴」聲 |
| 棋子放置成功 | 輕快「啵」聲 |
| 合成升星 | 上升音階＋閃亮鈴聲 |
| 戰鬥攻擊命中 | 輕巧短促打擊音 |
| 勝利 | 歡快小音階旋律 |
| 失敗 | 溫和不刺耳的下降音階（避免過度負面） |
| 頁面切換 | 輕柔「咻」聲 |

### 11.3 音量控制機制（含 10 倍音量需求的技術實作說明）

- 採用 **Web Audio API 的 `GainNode`** 而非單純 `<audio>.volume`（原生 `volume` 僅能在 0–1 之間，無法「放大超過原始音量」）。
- 設定頁的 BGM 音量滑桿範圍為 **0% ～ 1000%**，對應 `GainNode.gain.value` 的 `0 ～ 10.0`，實現「遊戲中 BGM 音量放大為原本的 10 倍」的需求，預設值建議落在合理的 **100%（即 1 倍，等同原始音量）**，讓使用者可依需求自行拉高至最大 10 倍。
- ⚠️ **技術與體驗提醒（設計備註，非規格刪減）**：由於音訊原始檔案在混音時已針對「正常音量（1 倍）」做響度優化，直接放大至 10 倍**極可能導致訊號削波失真（clipping）、破音，並有損害使用者聽力與喇叭設備的風險**。建議規格書內保留「最高可調至 10 倍」的滑桿上限以滿足需求，但實作時：
  1. 加入 `DynamicsCompressorNode`（動態壓縮器）於音訊輸出鏈尾端，在高倍率時自動抑制削波。
  2. 滑桿超過 300%（3 倍）時，於音量數值旁顯示小提示圖示「⚠️ 音量過大可能造成破音或不適，請留意音量」。
  3. 音效（SFX）音量倍率上限維持在較保守的 **0–300%**，避免高音頻音效在高倍率下產生刺耳尖銳聲。
- 音量設定儲存於 `localStorage`，跨場景（主畫面/遊戲內/說明/設定）保持一致。
- 靜音開關優先權最高：開啟靜音時，無論倍率為何，所有音訊 `gain` 立即設為 0。

## 12. 多國語系（i18n）系統

### 12.1 支援語言

- 🇹🇼 繁體中文（`zh-TW`，預設）
- 🇺🇸 英文（`en`）
- 🇯🇵 日文（`ja`）

### 12.2 技術實作方式

- 每個語言獨立為一個 JS 檔案，格式為巢狀物件：

```js
// js/i18n/lang-zh-TW.js
window.AutoBattlerLang = window.AutoBattlerLang || {};
window.AutoBattlerLang['zh-TW'] = {
  menu: {
    start: "開始遊戲",
    continue: "繼續遊戲",
    help: "遊戲說明",
    settings: "設定"
  },
  game: {
    gold: "金幣",
    round: "回合",
    health: "生命值"
  }
  // ...其餘依模組分類
};
```

- `i18n.js` 提供 `t(key)` 翻譯函式（支援點記法路徑，如 `t('menu.start')`），並負責：
  - 讀取 `localStorage` 中儲存的語言偏好，無則偵測 `navigator.language` 作為預設猜測，找不到對應語言則 fallback 為繁體中文。
  - 提供 `setLanguage(langCode)` 切換語言並即時重新渲染畫面上所有帶有 `data-i18n="key"` 屬性的元素。
- HTML 元素統一使用 `data-i18n` 屬性標記可翻譯文字，例如：

```html
<button data-i18n="menu.start">開始遊戲</button>
```

- 數字、日期格式若需在地化，使用 `Intl.NumberFormat` 依當前語言處理。
- 所有頁面（主畫面、遊戲內、說明、設定）**必須 100% 覆蓋翻譯**，不得有語言切換後仍顯示原文的殘留字串。

## 13. 存檔與繼續遊戲機制

- 使用 `localStorage`，儲存 key 例如 `autobattler_save`，內容包含：目前回合數、金幣、玩家血量、棋盤佈局、備戰區棋子、已解鎖設定等完整可還原遊戲狀態的 JSON。
- 每回合結算後自動存檔（Auto Save），避免玩家意外關閉分頁遺失進度。
- 「繼續遊戲」讀取存檔並還原至上次中斷的準確狀態（含商店當下內容，避免違和感可於讀檔時重新刷新商店）。
- 設定資料（語言、主題、音量）**獨立於遊戲存檔**，儲存於不同 key（例如 `autobattler_settings`），即使清除遊戲進度也不會被清掉。

## 14. 效能與流暢度優化

> 重點需求：動作流暢、不卡頓。

- **動畫一律使用 CSS `transform` / `opacity`**（觸發 GPU 合成層），避免使用會觸發 layout reflow 的屬性（如直接改 `top`/`left`/`width`）做動畫。
- 戰鬥特效若使用 Canvas，統一使用 `requestAnimationFrame` 驅動渲染迴圈，避免 `setInterval` 造成的掉幀。
- 圖片資源：
  - 角色圖／圖示優先使用 **SVG**（向量、檔案小、任何解析度都清晰），複雜插畫類使用壓縮後的 **WebP**（附 PNG fallback）。
  - 使用 CSS Sprite 或雪碧圖技術合併小型 UI 圖示，減少 HTTP 請求數（雖為本地檔案，仍有助於降低瀏覽器資源開銷）。
- 事件監聽採用**事件委派（Event Delegation）**，避免為每張商店卡片、每個棋盤格個別綁定大量事件監聽器。
- 手機裝置偵測後自動降級特效（例如減少背景飄動裝飾物數量、降低戰鬥特效粒子數），確保低階裝置仍維持 30–60 FPS。
- 音訊與圖片資源建議採**預先載入（preload）+ 載入進度畫面**，避免遊戲進行中因資源延遲載入造成卡頓。
- 避免 memory leak：場景切換時（menu → game → menu）需明確移除不再使用的事件監聽器與計時器（`clearInterval`/`removeEventListener`）。

## 15. 圖示與美術資產規範

> 重點需求：圖示要可愛有趣。

- 全站圖示風格統一：**圓潤線條、粗細一致（stroke-width 一致）、飽和度稍高、帶有俏皮表情或動態感**（例如金幣圖示帶笑臉、愛心圖示會跳動）。
- UI 圖示建議自繪 SVG（方便換色配合主題），常用圖示清單：
  - 導覽類：▶ 開始、⏯ 繼續、📖 說明、⚙️ 設定、🏠 首頁、🔙 返回
  - 資源類：💰 金幣、❤️ 生命、⭐ 星級、🎲 刷新、🔒 鎖定
  - 音訊類：🔊 音量、🔇 靜音、🎵 音樂
